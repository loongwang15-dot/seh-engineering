# SEH 验收矩阵

每个适用用例记录实际输入、预期、观察结果、文件或目标应用证据、PASS/FAIL/UNVERIFIED。文档描述不能充当实际运行结果。

| 用例 | 可观察的通过条件 |
| --- | --- |
| 正常请求 | 正确触发目标 Skill，按合同输出并通过适用 QA。 |
| 缺少关键输入 | 进入 WAITING_INPUT，指出具体缺项，不虚构最终产物。 |
| 边界外请求 | 不抢其他 Skill 职责，清楚路由或说明边界。 |
| Trigger 冲突 | 记录双方规则，按具体职责优先；不可裁决时阻断相关阶段。 |
| 过程失败 | 保存有效产物、错误原因和恢复入口。 |
| 定向重试 | 修正动作对应失败原因，重新 QA，次数不超过上限。 |
| 完成 | 输出满足锁定 Baseline，有实际 QA 证据和停止记录。 |
| 回归 | 旧 Trigger、输入、Workflow、输出和 QA 的代表性行为仍成立。 |
| Adapter 保真 | 每条适用 Source Requirement 都有目标规则和语义等价证据。 |
| 目标应用运行 | 实测可发现性、正反触发、路由、状态、QA、停止条件；不可测试项记 UNVERIFIED。 |

结构检查只证明文件与字段存在。功能检查需要执行例子，回归检查需要旧版行为对照，部署检查需要目标应用证据。仅在实际涉及视觉、中文文字或 IP 资产时增补对应专项 QA。适用门槛任一 FAIL 则整体 BLOCKED；必要运行证据缺失则整体 UNVERIFIED。
