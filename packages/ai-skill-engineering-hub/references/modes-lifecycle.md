# 审计、部署与废弃

## AUDIT

必需：审查对象或可用于定位它的名称。先查现有源、安装版和证据；未知文件可说明缺口，不要求为审计先完成部署。

执行：只读盘点 → 对照用户审查范围选择标准 → 查真实输入、输出、测试和版本证据 → 分开评估结构、行为、兼容性与必要性 → 按影响提出优先修复项。

产物：发现、证据位置、影响、建议和结论。审计不修改被审对象，不创建 Adapter、不强制要求回滚点或 Source → Runtime 映射；审计自身记录可以在用户允许的工作区保存。发现 FAIL 是被审对象的结果，审计任务仍可 COMPLETED。结构审计可以 PASS，未检验的完整行为 UNVERIFIED；不把检查范围之外的项目自动记失败。

必要性评估：识别现有通用能力无法稳定处理的重复问题、与其他 Skill 的重叠、真实使用频率、遗漏/返工/成本。没有对照数据时给出有条件判断，不宣称收益已证实。

## DEPLOY

必需：已确定的源版本、目标目录/账号/应用、当前授权和目标访问。明确安装位置；软件代码、当前项目和独立交付物按用户与环境目录规则放置。

执行：检查适用发布门 → 核对目标旧版与实际依赖 → 保存可恢复旧版 → 构建仅含实际需要文件的包 → 在权限允许范围安装 → 逐文件回读比对 → 验证目标发现、正确/错误触发、关键正常流程、异常与停止 → 报告各层结果。

只有安装授权而目标行为尚未完成时，可安装验证候选并明确状态；正式生产发布须满足相关运行门。平台新增元数据单列核对；未授权覆盖现有文件不得执行。安装被拒绝时先完成不依赖安装的构建/验证，报告具体阻断动作与权限原因。

产物：平台包、源版本、安装位置、旧版恢复点、回读差异、目标应用实测证据。文件一致只证明复制成功；新会话可发现性和实际执行才是目标应用证据。当前会话加载旧规则时不能据此判定新版已生效。某宿主不能访问时保留 UNVERIFIED，不伪造成功。

回滚：保留安装前文件清单与哈希；恢复已被本次替换的文件，移除本次新增文件时逐项验证其路径与哈希，防止删除其他任务改动。目标已有后续改动先比较，再决定恢复。失败不覆盖可用旧版。

## DEPRECATE

必需：目标版本/能力及用户废弃意图。归档、停用和删除分别判断授权；废弃不自动授权删除。

执行：检查实际引用、安装和使用证据 → 提出替代与兼容方案 → 保存完整旧源 → 修改已授权的生命周期登记/路由 → 验证替代调用与依赖 → 报告未迁移调用方。

产物：DEPRECATED/ARCHIVED 记录、迁移清单、来源和恢复方法。存在仍使用旧接口的调用方时保留兼容入口或阻断实际移除，其他工作继续。用户明确要求删除也须遵守文件权限和路径安全。无真实使用数据时写“未核实”，不推断零使用。
