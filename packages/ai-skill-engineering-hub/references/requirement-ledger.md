# 需求台账与 CR 记录

每条需求一行；ID 一旦建立，不因排序或措辞修改而重用。来源可以是用户原话、现有 Canonical 的文件与章节，或明确标记的建议。建议在确认前不得进入锁定 Baseline。

| ID | 来源 | 原要求或能力 | 优先级 | 适用范围 | 目标规则/产物 | 验收方法与证据 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| REQ-001 | 用户/文件位置 |  | CRITICAL/IMPORTANT/OPTIONAL |  |  |  | OPEN/VERIFIED/BLOCKED/N/A |

Baseline：ID、锁定时间、纳入的需求 ID、明确排除项、确认依据。

CR：ID、提出者及原话、关联 Baseline、受影响需求 ID、影响等级与理由、受影响模块、拟改动、批准或确认依据、版本影响、回归用例、结果。低影响且已由用户授权的变更可直接执行并留痕；不能自行把新能力加入 Canonical。

Source → Runtime 映射：每条需求填写 Source ID/位置、目标平台文件/位置、语义等价说明、检查方式、结论。目标不存在、规则弱化、未授权新增或仅以摘要替代时记 BLOCKED。
