# 需求台账与 CR 记录

每条需求一行；ID 一旦建立，不因排序或措辞修改而重用。来源可以是用户原话、现有 Canonical 的文件与章节，或明确标记的建议。建议在确认前不得进入锁定 Baseline。

| ID | 来源 | 原要求或能力 | 优先级 | 适用范围 | 目标规则/产物 | 验收方法与证据 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| REQ-001 | 用户/文件位置 |  | CRITICAL/IMPORTANT/OPTIONAL |  |  |  | OPEN/VERIFIED/BLOCKED/N/A |

Baseline：ID、锁定时间、纳入的需求 ID、明确排除项、确认依据。

CR：ID、提出者及原话、关联 Baseline、受影响需求 ID、影响等级与理由、受影响模块、拟改动、授权依据、版本影响、回归用例、结果。明确请求可作为授权依据，后续用户要求可更新基线；不重复请求已获得的确认。实现选择与新增用户能力要求分别记录。

能力或 Source → Runtime 映射：源 ID/位置/哈希、目标文件/规则、处理方式、语义说明、关联 CR 和验证。处理方式为 preserved / merged / conditional / changed / removed。去重、按需拆分和语义等价重写允许；能力损失或未经授权的新增须记录并阻断相关门。不要用摘要冒充完整能力恢复。审计不要求先生成映射或 Adapter；LIGHT 可内联记录变更。

FULL 的任务记录还包括 Stage/State、最近有效检查、产物与下一步。任何“覆盖数”都注明是本次需求、源章节还是实际行为；文件映射覆盖率不能冒充语义或运行通过率。
