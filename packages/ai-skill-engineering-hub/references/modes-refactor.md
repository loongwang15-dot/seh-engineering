# 拆分、合并与迁移

这些模式默认 FULL。按能力与调用边界处理，不按文档长度机械操作。

## SPLIT

必需：完整父源、拆分目标和实际调用需求。目标范围可从用户要求提取；涉及未知接口时询问。

执行：建立父能力清单 → 找到独立触发/输入输出边界 → 分配能力和依赖 → 为可独立调用的子 Skill 写入口，为内部步骤写普通模块 → 更新父路由 → 检查遗漏、重复所有权与循环 → 执行单子任务、跨子协作、越界和旧父任务。

产物：子 Skill/模块、父路由、依赖图或表、Source → 子规则映射、版本和恢复点。通过条件：全部适用父能力有归属，每个独立 Skill 有自己的触发、合同和验收；共享规则仅维护一份，相关调用有明示路径。拆分不授予新增权限。

区分“完整包内独立显式调用”和“可独立安装/发现”。用户需要独立部署时，每个子包须带齐本地依赖，或声明目标真实可用的共享依赖；不能依靠拆出后不存在的 ../../ 路径。共享 Canonical 只维护一份，子发行包可带有追踪来源/版本的生成副本，不能各自暗改它。分别以每个子包根做引用检查，并在隔离副本核对可读取性；目标宿主是否自动发现仍须实测。宿主只支持单入口时使用内部模块或声明受限候选，不宣称多入口自动可用。

## MERGE

必需：所有待合并源及用户合并目标。来源缺失时可先做冲突分析，不能宣称完整合并。

执行：比较职责/触发/约束 → 建立并集能力基线 → 消除等价重复 → 对冲突应用用户要求或明确优先级 → 设计统一入口与模式 → 映射各源 → 执行各旧能力和跨能力场景。

产物：合并源、能力/冲突映射、旧版快照、验证。通过条件：旧能力有新归属或授权变更，互斥规则有裁决，用户未授权的新能力为零。未裁决冲突只阻断受影响能力；不要用复制粘贴掩盖不一致。是否停用旧版由用户要求和依赖决定。

## MIGRATE

必需：Canonical、目标平台及能影响实现的实际限制/接口资料。优先读取目标环境中可核实信息；未知限制不得猜测。涉及平台最新信息时遵循宿主的检索要求。

执行：盘点能力和平台差异 → 建立逐项语义映射 → 仅转换格式、组织与调用机制 → 检查目标依赖 → 执行功能、边界、异常和回归 → 交付候选及平台限制。

产物：Adapter/平台包、来源与版本、映射、验证和同步说明。同内容复制可用哈希证明保真；重写后的语义必须另行核对。目标不能实现某能力时如实记录，寻求已授权替代或交付受限候选，不能暗中删除。

迁移通过是特定范围的等价迁移，不等于已安装。真实安装按 DEPLOY 执行；目标不可访问时目标行为 UNVERIFIED，离线构建可以完成。
