# 治理与适用性

冲突盘点按实际需要覆盖触发、边界、输出、流程、QA、状态、资产和平台；按入口统一规则处理，不为每一类建立额外流程。

## 工程标准

以下 24 项是检查维度，不是固定章节或目录。缺失某项只有在它对当前能力必需时才阻断生产资格。

| 维度 | 适用要求 |
| --- | --- |
| Identity / Purpose / Trigger / Boundary | 必须让宿主识别能力、触发及排除条件；具体生产职责优先。 |
| Input / Dependencies / Output | 必需输入、可推导默认、真实依赖和可验收结果；不得假设不存在的工具或资产。 |
| Workflow / State / Workflow Lock / Observability | 按任务复杂度给出可执行流程；简单任务可用短步骤和进度，长期任务须有恢复状态及记录。 |
| QA / Retry / Error Handling / Human Review / Stop Conditions | 说明实际质量判断、失败响应、必要介入和结束条件；专项检查仅按真实内容适用。 |
| Requirement Baseline / CR | 保留用户约束及授权变化；LIGHT 可内联记录，FULL 使用稳定 ID。 |
| Asset Interface | 只有调用外部或共享资产时声明 ID/位置、版本、用途和限制；无资产记 N/A。 |
| Version / Changelog / Test Cases | 修改留差异与可恢复来源；用例验证决策或成果，不能仅匹配措辞。 |
| Deployment / Maintenance | 部署才要求目标平台门；长期能力按实际失败和使用数据迭代。 |

触发设计包含使用场景、排除、识别信号、必要优先级和冲突处理；不要求用这五个名称作章节。边界注明实际上游和下游，仅有依赖时建立接口。独立 Skill 自包含，引用可读取；内部模块不能冒充独立可发现的 Skill。

## Canonical、Adapter 与角色

Canonical 是本任务登记的能力真源，不要求特定目录或平台。唯一来源须有文件、版本及确认依据；冲突版本不可未经分析覆盖。Adapter 转换表达、结构和调用形式，不能暗改职责、触发、输入输出、流程、QA、状态或停止条件。用户要求改变能力时更新 Canonical，再同步 Adapter。

Master 协调实际可用的生产能力；Production 执行；QA 检查；Asset 管理资产；Adapter 管理平台差异。角色只在实际多能力项目需要时实例化。SEH 可向项目、知识、资产、流程、工具和 QA 系统提供记录接口，但不宣称这些系统已接通。

层级、注册表、知识库、状态存储、失败库是可选集成。写明真实路径/接口、责任版本及调用证据后才算接入。SEH 软件 v1.0.0 另有 legacy 包目录检查；本 Skill 的最小有效文件结构使用自己的离线检查，不因旧检查器要求制造占位目录。

## 变更与保真

需求基线锁住“已确认的当前要求”，可由用户后续要求更新。CR 记录来源、影响和授权：低影响继续；中影响重排当前阶段；高影响重建相关流程。重大变化不自动触发例行批准；只有缺少必要决定或实际权限时才询问。

能力映射按语义单元记录：源位置/哈希 → 当前规则/产物 → 处理方式（preserved/merged/conditional/changed/removed）→ 保真说明或 CR 授权 → 验证。重组和去重允许，含义损失须有授权。缺失来源、未经授权的弱化或新增能力阻断相应保真门；新实现选择和新用户要求不能混写成历史要求。

合并、拆分、恢复和迁移必须映射关键旧能力；普通格式修订不强迫逐行映射。历史原件保留在项目归档，不放入运行包以免形成冲突指令。找不到完整源时交付可追踪候选，标明缺口；不能靠模型记忆宣称完整恢复。

## 状态恢复与运行记录

需要持久状态时记录 Task ID、Skill/Version、开始/结束时间、源哈希、Baseline/CR、阶段/状态、输入输出位置、QA、重试计数、错误及下一步。恢复先检查文件是否变化，废弃过时 PASS，重跑受影响门；对未改变部分保留可核实结果。

输入有效后可分析；需求和必要依赖明确后执行；当前产物存在后验证；适用 QA 完成后交付。AUDIT 的产物是报告，不需要先修改源或建立 Adapter。BLOCKED 保留已完成的独立成果；ERROR 保存错误与恢复入口。状态由代理记录，宿主是否自动持久化须实测。

重试针对输入、工具、流程或结果的可修正原因，默认最多 3 次。耗尽后交付已有效部分、失败与下一步；必要用户决策时提供具体待决项。人工审查用于真实歧义、关键身份/文字/视觉偏差、冲突及不可恢复失败，不为可判断的例行修订增加批准。

## 专项 QA

Visual 仅用于真实图像或视觉产物：检查构图、比例、层级、焦点、风格、颜色、材质、人物/动作、空间和细节。Consistency 仅涉及需要一致的资产：IP、角色、服装、造型、色彩、视觉语言和参考资产。

中文字体或图中文字实际存在时执行独立 Text QA：完整性、错/漏/重复字、笔画、结构、乱码、变形、层级与可读性。明显文字错误不可当成功交付。输出按用户实际规格检查尺寸/比例、格式、透明度、分辨率、命名和数量；无这些约束时不制造要求。

## 生命周期与效果

可使用 IDEA → PROTOTYPE → TESTING → VALIDATED → STABLE → PRODUCTION → OPTIMIZATION → DEPRECATED → ARCHIVED 记录生命周期，但不能仅按版本号晋级。生命周期与某次 QA 结果分开；生产资格依赖适用目标环境运行证据。

重要失败记录原因、分类、修正及回归，再决定规则或知识更新。维护记录实际触发命中/误触发、能力遗漏、返工次数、执行成本和恢复成功率；数据不足记未测。比较有/无 SEH 的同类任务时控制输入与范围，避免把文档增加误当收益。只根据已发生问题扩充规则。
